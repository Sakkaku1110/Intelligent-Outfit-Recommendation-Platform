# 云端 AI 预处理 + 边缘 AI 识别方案

## 结论

可行性较高，但建议把云端 AI API 定位为“主体提取/裁剪/背景干扰去除”，不要把最终衣物类别完全交给云端。

推荐链路：

```text
板子摄像头原图
  -> 取景框裁剪
  -> 云端 AI API 找衣物主体区域
  -> 输出主体 bbox/mask + 归一化裁剪图
  -> 板端/本地边缘模型识别固定 7 件衣物
  -> 人工审核确认
  -> 入库/训练/推荐
```

## 为什么这样设计

云端 AI API 更擅长理解复杂画面：比如手、衣架、桌面、床铺、背景杂物和衣物混在一起时，它能更稳地找出“真正要入库的衣物主体”。

边缘模型更适合做比赛演示中的固定分类：我们的目标不是识别全世界所有衣服，而是稳定识别固定衣柜里的 7 件衣物。把最终分类留给边缘模型，可以避免网络不稳定、API 延迟、费用和隐私问题。

## 云端 API 适合做的事

- 找出图片中的主衣物 bbox。
- 如果支持分割，输出衣物 mask。
- 去除背景，只保留衣物主体。
- 生成统一比例的训练图，例如 768x768 或 640x640。
- 给低质量图片打质量分：过暗、过曝、太糊、主体太小。

## 云端 API 不建议承担的事

- 不建议直接决定“这是蓝色球衣/白色 Polo/酒红卫衣”作为最终结果。
- 不建议在没有网络时让系统完全不可用。
- 不建议把比赛演示的实时推荐依赖外网 API。

## 边缘端继续负责的事

- 固定 7 件衣物的最终分类。
- 颜色、类别、材质的稳定输出。
- 离线演示能力。
- 和数据库、推荐算法、触控屏 UI 联动。

## 推荐落地方式

第一阶段先不改板端运行链路，只在数据集采集台中加入“云端主体提取”按钮：

1. 板子拍照生成取景框裁剪图。
2. 人工审核页显示原裁剪图。
3. 点击“AI 提取主体”。
4. 云端 API 返回主体裁剪图。
5. 人工确认后，把主体裁剪图存入数据集。

这样风险最低，因为即使 API 不可用，也可以继续使用原来的取景框裁剪图采集。

第二阶段再把同样的主体提取逻辑加入正式 AI 入库流程：

1. 有网络时使用云端主体提取。
2. 无网络时回退到板端取景框裁剪。
3. 最终识别仍交给边缘模型。

## 比赛答辩表述

本项目采用“云边协同”的视觉链路。云端模型负责复杂场景下的衣物主体定位和背景干扰剔除，边缘端模型负责固定衣柜物品的低延迟分类和推荐决策。这样既提高了入库图片质量，也保留了嵌入式系统的本地运行能力。
